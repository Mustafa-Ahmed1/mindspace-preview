Widget kit

Seventeen widget types cover what an ERP and a super app need to show on a Home or a dashboard. A type decides how a widget looks at each size, on the desktop canvas and on a phone. A module only supplies data: Finance, Sales, People, Operations, Payments or a new mini app all use the same types, so every product built on Mindspace gets the same widgets.

Home

A Home built only from kit types, on the canvas and on a phone. Approve or decline a request, tick a task, switch a period, check in, vote, tap the mic. Edit to drag, resize, remove, and add from the gallery. “Send an update” changes data the way a live feed does.

Types

Pick a type to see every size it supports on the desktop canvas and on a phone. Types with kinds (a list of approvals, of tasks, of files…) show one kind at a time. Each type lists what it’s for and the data it takes.

By product

The same types filled with each area’s data: what a module ships as presets for the widget gallery. Nothing here needed a new type.

States

Every type has the same states, and the header always stays. Loading shows a skeleton in the shape of the content. Data can also be live, or old with a way to refresh.

One job per widget

A widget answers one question for one person. If it needs a second question, it’s two widgets. If it needs a page, its title opens the page.

Sizes

Small 1 × 1, Medium 2 × 1, Large 2 × 2, Wide 4 × 2 on a grid of 160px columns and 132px rows, 12px apart. Wide draws as Large when fewer than four columns fit. A type lays its content out again for each size; it never just shrinks.

Phone

Under 560px the grid becomes two columns of square cells in the same order. Text is 15px, figures 28px, buttons 36px, and rows grow to 44 or 50px so every target can be tapped.

Numbers

Tabular digits, the unit dim beside the figure. Every change has a direction and says which way is good: more revenue is green, more overdue invoices is red. Money shows its currency once, in the unit.

Colour

The accent marks the current or live value. Green, amber and red are for status only. Charts use the categorical palette in a fixed order. Only an announcement has a coloured surface.

Periods and freshness

A widget that shows a period has a period menu in its header. Live data says Live. Data that couldn’t refresh says “As of 9:40 AM” with Refresh, instead of showing old numbers as new.

Actions

At most one button, and it’s neutral; approvals get approve and decline on each row. Everything else opens: the title opens the module, a row opens the record, a bar opens that period.

Access

The gallery only offers widgets the person can see. If access is removed later, the widget stays where it was and shows “No access” with Request access, so the layout never jumps.

Layouts

Each role gets a default Home (finance, sales, HR, operations, staff). A person can edit theirs; it’s saved per person and per space, and Reset returns to the role’s default.

Loading

A widget loads its own data and shows a skeleton until it arrives, so a slow module never holds up the Home. Widgets below the fold load when they scroll into view.

Motion

Values cross-fade when they change and bars move to their new length. Approved rows tint, close up and the next one slides in. Add scales in, remove shrinks out, reorder slides. Reduced motion jumps to the end.

Writing

Titles are what the widget shows (“Invoices to approve”), not the module (“Accounting”). Captions say what the number means: “Across 4 accounts”, “5 waiting on you”.

Handoff

For developers and Claude Code. One stylesheet and one script on top of the design system you already have.

  1. Port. <style id="widgets-css"> becomes design-system/components/widget.css. <script id="widgets-js"> goes into ui.js as the widget module; it uses the ui.js helpers and exposes window.MSW. Add the ten new icons to the icon set: eye, eyeoff, car, box, truck, cart, card, gift, food, receipt.
  2. Replace. The canvas and the phone’s Home become one MSW.grid each. This replaces the widget file from yesterday (types app, folder, tasks, log, attendance, count, stat, summary, actions, ask) and the old .x-* and .m-* widget markup. The table below says what each old widget becomes.
  3. Presets. Each module registers its widgets with MSW.preset(): a type, a size, a title, a category for the gallery, and a load() that returns data. Modules never write widget markup.
  4. Layouts. Save grid.layout() per person and space; load a role’s default when there’s none. Only offer presets the person has access to.
  5. Wire. onOpen(widget, target) opens the module, record or action. onAction(widget, action, item) sends approvals, ticks, check-ins, votes and expenses to the server; the widget has already updated.
  6. Check. Every type at every size in dark and light, every space colour, a canvas from 2 to 8 columns, a phone at 360px, keyboard in edit mode, reduced motion, and right-to-left for Arabic.
// 1. a module registers presets: the gallery lists them, a layout refers to them
MSW.preset('finance.cash', { type: 'metric', size: 'm', title: 'Cash position', icon: 'bank', category: 'Finance',
  load: async ({ period }) => {
    const r = await api.get('/finance/cash', { period });
    return { value: r.total, unit: 'M IQD', delta: r.change, dir: r.change < 0 ? 'down' : 'up', caption: `Across ${r.accounts} accounts`,
             series: r.daily, labels: r.days, periods: ['30 days', '90 days', 'This year'], period };
  } });

// 2. a Home: the canvas or the phone (phone under 560px wide)
const home = MSW.grid(el, {
  onOpen(widget, target) {},                 // title, row or button: open the module, the record or the action
  onAction(widget, action, item) {},         // 'approve' | 'decline' | 'done' | 'check in' | 'vote' | 'submit' …
  onChange(layout) { save(layout); },        // order or size changed
});
home.load(savedLayout ?? roleDefault);       // [{ preset: 'finance.cash', size: 'l' }, { type: 'list', data: {…} }]

// 3. a widget
const w = home.add({ preset: 'sales.pipeline' });
w.update({ stages });                        // only the values that changed cross-fade
w.reload({ period: 'This quarter' });        // loading, then ready, empty or error
w.setState('locked');                        // 'loading' | 'empty' | 'error' | 'locked' | 'ready'
home.resize(w.id, 'l'); home.move(w.id, 0); home.remove(w.id); home.edit(true);

  render(data, { fit, phone }) { return `…header and body for this fit…`; } });
